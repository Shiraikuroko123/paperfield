# 原 35 题课程附录

这里保留原项目式课程附录，包括最小实验环境、项目报告结构、技术边界和核心参考资料。新的学习日志、术语表和版本说明位于同级独立页面。
## 附录 A：不需要 GPU 的最小实验环境

前 14 个项目的大部分核心结论，都可以用手算、NumPy 或很小的 PyTorch 模型验证。不要一开始就安装完整 RL 集群。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install numpy matplotlib torch
```

没有 NVIDIA GPU 也没关系。bandit、两动作 policy、PPO clip 曲线、group advantage、DPO pairwise loss 和双 rank 分母模拟都可以在 CPU 上运行。第 20 章之后的显存与通信项目，可以先用“时间账本”和 profiler 日志学习；真正有多卡环境时再复现吞吐。

每个实验固定保存以下信息：

```text
seed, code commit, model/checkpoint, tokenizer
prompt set, sampling temperature/top-p/top-k
reward/verifier version, policy version
loss numerator, loss denominator, effective token count
reward, KL, entropy, ratio p50/p99, gradient norm
wall time, generated tokens, accepted/stale tokens
```

只报告最终 reward 不足以判断算法正确。最小验收是：能用一个手算样本对齐中间量，再扩大 batch。

## 附录 B：一份项目报告应该写什么

每完成一章，用下面的结构写一页报告：

1. **问题**：我在日志中看到了什么异常？
2. **假设**：我认为是哪一个分母、概率分布、版本或硬件阶段导致的？
3. **最小实验**：只改变一个变量，其余条件固定。
4. **手算基准**：至少有一条样本能在纸上算出正确中间值。
5. **观测**：同时报告质量、稳定性、吞吐和资源，不只挑最好看的数。
6. **结论边界**：说明结论依赖的模型、数据、采样器、commit 和预算。
7. **下一问**：如果把动作数、序列长度、GPU 数或 staleness 放大，会怎样？

这比背一句“某方法优于 GRPO”更接近真实面试和工程工作。面试官真正关心的是你能否定义比较、找到反例并设计验证。

## 附录 C：全书必须守住的技术边界

- 终局 reward 在 $\gamma=1$ 时作为每个 response token 的 Monte Carlo 回报，在数学上可以成立；问题是方差高、credit assignment 粗，而不是“绝对错误”。
- $\operatorname{pass@}k=1-(1-p)^k$ 只是在固定 prompt、相同采样配置且各次近似独立时的基线。真实候选相关、选择器会错，不能把它当作普适上界。
- GRPO 的组均值若包含当前样本，会带来约 $(G-1)/G$ 的梯度尺度效应；leave-one-out baseline 是另一种估计器，不能混写。
- PPO 的 $\pi_\theta/\pi_{\mathrm{old}}$、reference KL 的 $\pi_\theta/\pi_{\mathrm{ref}}$ 与 DPO 的偏好 log-ratio 分别回答不同问题。
- “一个采样公式能无偏估计 KL 的数值”不自动推出“直接对这个标量反向传播就得到无偏 KL 梯度”。采样分布和 stop-gradient 路径必须一起检查。
- DPO 是 Bradley--Terry 偏好事件上的 pairwise 交叉熵/最大似然，不是对 chosen response 做普通 token-level MLE。
- MaxRL 优化成功事件下潜在正确轨迹的边缘似然；它不是挑一条正确 CoT 后做普通 MLE。
- MoE 训推不一致不会自动使 importance sampling 失效。真正危险的是把 trainer 重算的 log-prob 冒充实际 rollout behavior 的分母。
- 普通、非 autograd-aware 的 `all_reduce(loss.detach())` 只改日志数值，不会把梯度乘以 `world_size`。必须区分日志归约、可微 loss 归约和 DDP/FSDP 梯度归约。
- 任何 group size、learning rate、generation length、可接受 staleness 或显存数字，都只是某个模型和系统的实验起点，不是跨项目定律。
