## 学习目标

- 画出数据进入模型、模型生成 token、反馈进入训练的完整链路；
- 区分预训练、SFT、偏好优化、RL 和推理时搜索；
- 知道 35 题分别处在算法、系统和评测链路的哪里。

## 1. 一条样本的生命周期

```mermaid
flowchart LR
    A[原始数据] --> B[清洗 去重 混合]
    B --> C[Tokenizer]
    C --> D[预训练 next-token loss]
    D --> E[SFT 指令与回答]
    E --> F[偏好优化或 RL]
    F --> G[推理引擎]
    G --> H[评测与真实反馈]
    H --> B
```

这个闭环有三条不能混淆的线：

- **模型线**：参数如何把上下文映射成下一个 token 的概率分布；
- **数据线**：样本从哪里来、如何筛选、如何形成 loss 和权重；
- **系统线**：样本如何在 GPU、队列、缓存与 worker 之间移动。

算法改动只有放回这三条线，才能判断它到底改变了能力、数据分布还是吞吐。

## 2. 六个训练阶段

| 阶段 | 输入 | 直接目标 | 典型风险 |
|---|---|---|---|
| Tokenizer 训练 | 文本或字节 | 建立有限词表与编码规则 | 多语言切分差、未知字符、版本漂移 |
| 预训练 | 大规模 token 序列 | 最大化下一个 token 似然 | 数据污染、重复、loss spike、算力浪费 |
| SFT | 指令-回答或对话 | 学习期望输出格式和行为 | label mask 错、模板不一致、过拟合风格 |
| 偏好优化 | chosen/rejected 或评分 | 提高相对偏好 | 偏好噪声、长度偏置、分布外失效 |
| 在线 RL | prompt、rollout、reward | 提升可验证结果或综合奖励 | reward hacking、staleness、训练崩溃 |
| 推理时扩展 | 同一模型的多次采样/搜索 | 在预算内提高成功概率 | 成本上升、选择器偏差、结果相关性 |

## 3. 必须统一的术语

| 术语 | 本课程中的含义 |
|---|---|
| token | tokenizer 输出的离散 id；不等于字、词或字符 |
| logit | softmax 之前的未归一化分数 |
| log-prob | 某 token 在当前上下文下的对数概率 |
| sequence | 一段 token 序列；通常包含 prompt 和 response |
| checkpoint | 某一步的参数、优化器、调度器和训练状态快照 |
| rollout | 当前或指定策略针对 prompt 采样出的回答及其元数据 |
| reward | 对结果或行为的评分信号，不等于真实目标本身 |
| advantage | 某动作/回答相对基线“好多少”的估计 |
| reference policy | 用于约束漂移或定义偏好的固定参考模型 |
| staleness | 生成样本的策略版本与训练当前版本之间的距离 |

## 4. 35 题的三段位置

- **P01-P12：对齐与 RL 基础。** 从 policy gradient、KL、reward、advantage 到 PPO、GRPO、DPO 和超参数。
- **P13-P19：方法与前沿。** 比较新方法到底修改目标、估计器、采样还是约束，并训练证据边界。
- **P20-P35：训练与推理系统。** 显存、KV cache、低精度、长尾、continuous batching、并行、异步和框架选型。

## 5. 一个专家式问题模板

面对任何新方法，先问：

1. 它解决了哪个可观察故障？
2. 它改变了目标函数、梯度估计、数据分布还是系统调度？
3. 与哪个最小 baseline 比较才公平？
4. 改进来自更多算力、更多样本还是算法本身？
5. 在哪些分布、长度、模型规模和系统设置下证据成立？
6. 需要记录哪些日志才能证伪作者解释？
