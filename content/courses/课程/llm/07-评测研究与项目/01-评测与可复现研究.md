## 1. 评测合同

实验开始前写下：

| 项目 | 必须冻结的内容 |
|---|---|
| Claim | 要验证的单句主张，以及不主张什么 |
| Dataset | 来源、版本、split、去重/污染检查、许可 |
| Model | 权重与 tokenizer hash、模板、精度、最大长度 |
| Generation | temperature、top-k/top-p、seed、停止条件、预算 |
| Metric | 公式、聚合轴、无效样本处理、方向 |
| Baseline | 最强相关基线与最小朴素基线 |
| Statistics | 重复次数、置信区间、配对检验或 bootstrap |
| Resources | 硬件、时间、token、费用与失败运行 |

先看结果再选择指标、样本或 seed，会把探索变成选择性报告。

## 2. 指标必须匹配任务

- 可验证数学/代码：pass@k、准确率、编译/测试通过率，但要公开采样预算和验证器；
- 开放生成：人工 rubric、成对偏好或任务特定指标，说明标注者和一致性；
- 检索增强：retrieval recall、引用覆盖、答案正确、引用支持率分别报告；
- Serving：TTFT、ITL、P50/P95/P99、吞吐、错误率和负载曲线；
- RL 训练：任务 reward 之外同时报告 KL、长度、entropy、clip fraction、staleness 和失败类别。

一个标量不能概括所有目标。质量、成本、延迟和安全至少要形成 Pareto 视图。

## 3. 不确定性与配对比较

对于样本 $i$，比较方法 A/B 的差值 $d_i=s_i^A-s_i^B$。配对分析利用“同一道题”的相关性，通常比把两组独立处理更有力。

Bootstrap 的基本做法：从 $N$ 个样本索引有放回抽样，重复计算平均差，使用分位数形成置信区间。区间跨 0 不等于两方法完全相同，只说明在当前样本和假设下证据不足。

同时报告效应量：提升 0.1 个百分点即使统计显著，也可能没有工程价值。

## 4. 失败分类比总分更接近机制

建立互斥、可复核的失败类别，例如：

- 输入解析/模板错误；
- 知识缺失；
- 推理链断裂；
- 生成格式错误；
- 验证器误判；
- 截断或超时；
- 服务/工具调用失败。

随机抽样人工复核自动分类，并保存典型样本。方法如果只改善某一类失败，结论应限定在该机制。
