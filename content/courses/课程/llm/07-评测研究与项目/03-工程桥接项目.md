本项目面向已经做过视觉推理、Qt/多线程、设备 SDK、ONNX 或端侧部署的学习者。公开实现只使用公开数据或人工合成日志，不需要也不允许上传企业代码、模型、图像、设备标识或实习材料。

## 项目题目：可审计的 LLM 故障诊断与推理基准

构造一个小型离线基准：输入是结构化系统事件和脱敏日志，模型需要给出故障类别、证据行、排查顺序和下一步操作。它把既有能力映射到 LLM 领域：

| 既有工程经验 | LLM 对应能力 |
|---|---|
| 相机采集、线程和帧队列 | 请求队列、continuous batching、rollout worker |
| ONNX 模型加载与推理 | tokenizer/model revision、serving backend 与精度 |
| 实时耗时记录 | TTFT、ITL、P50/P95、有效 tokens/s |
| 设备/格式/模型异常提示 | 结构化日志、失败分类与恢复策略 |
| 图像处理链路联调 | token、mask、KV cache 与跨组件数据契约 |

## 1. 数据集

生成或公开收集 500-2000 条事件序列，至少覆盖：

- 模型/Tokenizer 版本不一致；
- prompt 被截断或 chat template 错误；
- CUDA OOM、显存碎片和过长 KV cache；
- prefill 拥塞、decode 长尾和队列饥饿；
- 非有限 loss、梯度爆炸和 checkpoint 恢复错位；
- worker 版本 stale、权重同步超时和重复消费；
- 正常但容易误报的对照样本。

每条样本包含 `events`、`root_cause`、`evidence_event_ids`、`recommended_actions` 和难度标签。Train/test 按故障模板族分割，避免只记住字符串。

## 2. 三个 baseline

1. **规则系统**：关键词和状态机，提供可解释的朴素下限；
2. **检索 baseline**：从故障手册检索相关条目，再按固定模板回答；
3. **小型指令模型**：zero-shot/few-shot，必要时再做 LoRA。

必须先完成前两个 baseline，不能直接微调模型。

## 3. 评测

| 目标 | 指标 |
|---|---|
| 故障分类 | macro F1、每类 recall |
| 证据定位 | evidence precision/recall |
| 操作建议 | 必需步骤覆盖率、危险步骤率 |
| 引用可信度 | 建议是否由引用事件/手册支持 |
| 系统效率 | TTFT、P95、峰值内存、tokens/s |
| 稳健性 | 未见模板、噪声日志、顺序扰动、长上下文 |

## 4. 四个受控实验

- 无检索 vs 检索；
- 完整日志 vs 仅最后 20 条；
- 结构化 JSON vs 自然语言拼接；
- zero-shot vs few-shot vs LoRA（同评测集、明确额外训练成本）。

对每个实验保存失败样本，判断提升来自信息增加、格式改善还是模型参数更新。

## 5. 交付物

```text
README.md                 一条命令复现实验
data_card.md              来源、合成规则、split 与限制
configs/                  模型、检索、生成与评测配置
src/                      数据、baseline、推理和指标
tests/                    数据 schema 与关键指标单测
results/metrics.json      全部预注册运行
results/failures.jsonl    可复查失败样本
report.md                 claim、方法、结果、局限和下一步
```

## 进阶扩展

完成基础项目后再选一个：

- 用 vLLM/llama.cpp 对同一模型做负载曲线和 KV cache 账本；
- 把正确故障分类改成可验证 reward，完成一个极小 GRPO/偏好优化实验；
- 将公开视觉异常数据的检测输出转成结构化事件，研究多模态证据与文本诊断，但必须分开评测视觉错误和语言错误。
