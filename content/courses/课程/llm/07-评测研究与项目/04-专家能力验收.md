## 1. 五个能力维度

| 维度 | 合格产出 | 专家级证据 |
|---|---|---|
| 基础与模型 | 手算 attention、loss、KL；实现 tiny Transformer | 能定位 mask、数值与训练稳定性问题，并解释架构取舍 |
| 数据与训练 | 数据卡、SFT 样本审计、可恢复训练 | 能设计数据混合/污染实验，区分数据与算法贡献 |
| 对齐算法 | 完成 P01-P19 的核心实验 | 能统一比较目标与估计器，提出并验证失效条件 |
| 系统工程 | 完成显存、通信、时间、版本账本 | 能用 profile 和 golden batch 改进真实瓶颈且保持数值一致 |
| 评测与研究 | 评测合同、baseline、消融、统计和报告 | 能形成可证伪新假设，经独立复查仍成立 |

任何一维只有术语解释而没有实验证据，都不能称为该方向专家。

## 2. 三阶段作品集

### 阶段 A：基础可信

- labs 00-06 全部通过；
- 一份 tiny Transformer/语言模型实现说明；
- 一个训练故障的复现、定位和修复记录；
- 一个 tokenizer/SFT 样本审计报告。

### 阶段 B：工程可信

- 至少完成一个 P20-P35 系统项目；
- 同时报告质量、吞吐、延迟、内存和失败率；
- 有 profiler 证据、golden batch 和回归测试；
- README 能让他人在新环境复现。

### 阶段 C：研究可信

- 深度复现一篇相关论文；
- 与强 baseline 做同预算比较；
- 至少一个预注册消融和三个 seed；
- 报告失败样本、负结果和成立边界；
- 由其他人复跑关键表格或审查代码。

## 3. 口头压力测试

对作品准备四层回答：

1. **30 秒**：问题、方法和核心结果；
2. **3 分钟**：数据、baseline、指标、主要失败；
3. **白板推导**：一个关键公式和张量形状；
4. **反方追问**：为什么提升不是更多算力、数据污染或评测偏差？

如果只能演示成功案例，作品仍处于 demo 阶段。

## 4. 课程完成后的继续方式

1. 选定一个主线：训练算法、数据、推理系统、评测或应用研究；
2. 每月深读并复现一篇代表工作，而不是收集论文标题；
3. 从复现中的稳定失败提出最小可检验假设；
4. 保持同一套数据卡、评测合同、资源账和失败分类；
5. 定期回到 M0 诊断，更新缺口而不是无限扩展路线图。
