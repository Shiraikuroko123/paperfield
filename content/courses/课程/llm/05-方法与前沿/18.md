## 18.0 把“推理”拆成表征、行为、搜索

- 预训练主要提供语言/代码/数学表征和可组合知识；
- SFT 提供格式、步骤模板、工具协议；
- RL/RLVR 在反馈下重新分配成功轨迹概率；
- OPD 把 teacher 的搜索结果压缩进 student；
- TTS 只增加推理时搜索预算，不改参数。

所以不能只看某一个阶段的最终分数就断言“能力在这里产生”。

## 18.1 四 checkpoint 实验

准备 base、base+SFT、base+RL、base+SFT+RL。每个 checkpoint 固定推理 token 预算，测 greedy pass@1、pass@k、跨域迁移、错误 prefix 恢复率、轨迹长度和自检动作频率。

若 SFT 只提高格式而 RL 提高错误恢复，说明 RL 改变了行为策略；若 base 在极大 $k$ 下已偶尔找到同类解，RL 更像概率重分配而非注入新事实。

## 18.2 TTS 对照

TTS 生成 $k$ 条候选并由 verifier 选择：

$$
\hat y=\operatorname{select}(y^{(1)},\ldots,y^{(k)}).
$$

报告 RL 和 TTS 时固定总 token/cost；否则“RL 更强”可能只是它用了更多推理预算。

## 18.3 手算阶段贡献，避免把混淆当因果

下面是一个**教学用**结果表，不代表某个真实模型：

| checkpoint | greedy pass@1 | pass@16 | 错误 prefix 恢复率 |
|---|---:|---:|---:|
| base | 30% | 45% | 10% |
| base + SFT | 32% | 47% | 12% |
| base + RL | 42% | 58% | 31% |
| base + SFT + RL | 45% | 61% | 35% |

在这个 toy 表中，RL 的 greedy 增量约为 12 个百分点，SFT 的增量约为 2 个百分点；但不能直接说“RL 贡献 12%”，因为训练数据、步数和 token budget 仍可能不同。至少还要做 equal-compute 对照和多 seed。

每条评测记录 `checkpoint_id`、训练数据 hash、训练 token 数、推理 token budget、temperature、k、verifier_version、format_pass、answer_pass、recovery_pass、trajectory_length 和 self_check_count。典型故障是只给 RL checkpoint 更长的 `max_new_tokens`，日志却没有该字段，导致 TTS 增益被误归因于训练。

## 18.4 用一个概率模型区分“找到过”与“稳定做到”

把某个 prompt 在固定采样配置下得到正确答案的单次概率记为 $p$。在近似独立采样下，至少一次成功的概率是

$$
\operatorname{pass@}k\approx1-(1-p)^k.
$$

例如 base 的 $p=0.30$ 时，$k=16$ 的上限约为 $99.2\%$；如果 RL 把 $p$ 提到 $0.45$，$k=1$ 直接变成 45%，但 $k=16$ 只从 99.2% 进一步接近 99.96%。这说明大 $k$ 很容易把“已经偶尔找到”掩盖成“能力已经稳定”，所以要同时看 greedy/pass@1、错误恢复和答案多样性。这个独立性公式只是直觉工具，真实 CoT 样本往往相关，报告应给 bootstrap 置信区间。

可以把 checkpoint 阶段看成干预变量 $S$，把表征、格式行为、搜索预算和 verifier 规则看成其他变量。一个可辩护的比较是：固定 prompt 集、采样器、最大 token、verifier 和总生成 token，只改变 $S$；再用同一 checkpoint 做 `k=1,4,16` 的曲线。若 RL 只在大 $k$ 获益，可能只是多样性改变；若 pass@1、错误恢复和跨域都一起提升，才更像稳定策略或状态恢复能力变化。

最小伪代码如下，注意所有阶段使用相同评测协议：

```python
for checkpoint in ["base", "sft", "rl", "sft_rl"]:
    model = load(checkpoint)
    model.eval()
    for k in [1, 4, 16]:
        samples = generate_fixed_budget(model, prompts, k=k, seed=seed)
        rows = verify_and_label(samples, verifier_version=verifier_version)
        save_metrics(checkpoint, k, rows,
                     prompt_hash=prompt_hash,
                     token_budget=max_new_tokens,
                     sampling_config=sampling_config)
```

如果只测最终答案，无法知道模型是“更会想”还是“更会遵守格式”；把 `format_pass`、`answer_pass`、`recovery_pass` 分开，才能定位训练阶段改变了哪一层行为。

**验收标准**：四 checkpoint 在相同推理预算下评估；训练域、未见同域、跨域分开报告；至少 3 个 seed，并给出 pass@k 的置信区间。<br>
**追问**：怎样区分表征获得与概率重分配？为什么错误 prefix 恢复率比单一 pass@1 更有诊断价值？TTS 与 RL 的总成本应该如何对齐？
