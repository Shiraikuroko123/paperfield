## 19.0 资料纪律

本章将公开 technical report 明确写出的内容称作“公开事实”，将实现细节和未来版本称作“待核验”。引用入口：R1（arXiv:2501.12948）、V3.2（arXiv:2512.02556）、V4 preview（arXiv:2606.19348）。

## 19.1 R1 的路线

R1-Zero 展示 base model 直接做大规模 RLVR；R1 加入冷启动数据、多阶段 RL 与 SFT。数学/代码 verifier 和格式约束提供反馈，报告观察到反思、验证、动态策略行为。小模型蒸馏 R1 轨迹是能力传播，不等于小模型独立完成同等搜索。

## 19.2 V3.2 的训推一致性

公开报告描述可扩展 RL protocol、扩大 post-training compute、agentic task synthesis 和 DSA，并提到：

1. unbiased KL estimate：用 importance correction 估计 rollout/current 差异；
2. off-policy sequence masking：对高 divergence 或方向不利的旧序列 mask/降权；
3. keep routing / R3：缓存 rollout expert selection，训练重放；
4. keep sampling mask：保存 rollout 的 top-$p$/top-$k$ action support。

四者分别修 divergence、路由、采样支持，不能简化成“GRPO 加大规模”。

## 19.3 V4 preview 的 specialist RL 与 unified OPD

公开 preview 声称 specialist 先经 SFT 与 GRPO/RL；final unified stage 使用多教师 OPD、加权 reverse-KL、full-vocabulary logits distillation、teacher hidden-state cache、FP4 QAT 以及 batch-invariant/deterministic kernels（按报告版本核验）。因此“V4 不用 RL”不准确，变化是最终统一阶段的一段训练信号。

## 19.4 MoE 排错项目

固定 prompt 和 seed，逐层打开：权重/精度一致、router top-$k$ replay、sampler top-$p$/temperature support、deterministic kernel。每步比较 token log-prob、expert id 和最终 reward。第几步恢复，就指向哪一类 mismatch。

## 19.5 手算一个 MoE route mismatch

假设某 token 的四个专家 router 概率为 $(0.310,0.300,0.291,0.099)$，top-2 是专家 1、2。rollout 使用这两个专家；trainer 因为数值微小差异得到 $(0.310,0.291,0.300,0.099)$，top-2 变为专家 1、3。第二、第三名只交换了 $0.009$ 的概率质量，专家输出却可能完全不同，`old_logp` 与重算 log-prob 就会出现系统差异。

排错时保存：

~~~text
model_commit, weight_version, precision, kernel_flags, batch_shape,
prompt_hash, token_index, router_logits_topk, expert_ids,
sampling_support_hash, rollout_logp, trainer_logp, delta_logp
~~~

把 `expert_ids` 一致率和 `|delta_logp|` 分桶画图。若固定 route 后恢复、固定 lm-head 精度仍有差异，问题可能在 sampler support；若只有 deterministic kernel 后恢复，则是 reduction/batch invariance。

**验收标准**：同一 seed 的 route replay 一致率达到预设阈值；所有公开事实都能链接到报告段落，未公开系数标成“待核验”；不能用一次匹配就声称修复训推一致性。<br>
**追问**：R3/keep routing 能否修复 top-$p$ mismatch？为什么 V4 的 final OPD 不等于“完全没有 RL”？怎样区分论文事实和从日志推断的机制？
