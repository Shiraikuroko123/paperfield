## 26.0 先看一个数字错误

两个 data-parallel rank 各自有一批样本。rank 0 有 8 个有效 response token，loss numerator 是 8；rank 1 只有 2 个有效 token，numerator 是 0。真正的全局 token mean 是

$$
\frac{8+0}{8+2}=0.8.
$$

如果每个 rank 先求本地平均再平均，得到 $(1+0)/2=0.5$。长度不平衡时，两个结果差很多，这就是多卡 RL 中最常见的“loss 看起来正常但梯度比例错了”问题。

## 26.1 rollout 为什么不直接反传

策略从 prompt $x$ 生成序列 $y$，目标是

$$
J(\theta)=\mathbb{E}_{y\sim\pi_\theta}[R(y)].
$$

硬采样 token 是一次离散选择：若把“选中了哪个 token”当作普通计算节点，常规自动微分没有一条可导路径从 reward 穿回 logits。policy gradient 绕开了这条路径，改用 score-function/REINFORCE 估计器；它是可用的无偏估计器，但方差通常很大，所以工程上还会加入 baseline、advantage normalization 或更大的采样组。利用恒等式

$$
\nabla_\theta J
=\mathbb{E}\left[R(y)\nabla_\theta\log\pi_\theta(y\mid x)\right],
$$

再利用自回归分解

$$
\log\pi_\theta(y\mid x)
=\sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t}),
$$

训练器只需重新 forward 得到每个已生成 token 的 `new_logp`，再与 rollout 时记录的 behavior `old_logp` 构造 ratio。环境、verifier、采样随机数都停留在 forward 之外。

## 26.2 从一个样本推到 PPO token loss

设 $m_{i,t}=1$ 表示第 $t$ 个 token 是有效 response，$A_i$ 是该 response 的 advantage。PPO 的逐 token surrogate 是

$$
\ell_{i,t}
=-m_{i,t}\min\left(\rho_{i,t}A_i,
\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_i\right),
$$

其中

$$
\rho_{i,t}=\exp\left(\log p_{new,i,t}-\log p_{old,i,t}\right).
$$

$\rho=1$ 表示新旧策略给该 token 相同概率；$\rho=1.2$ 表示新策略概率高 20%。先对有效 token 求和，再除以全局有效 token 数：

$$
L=\frac{\sum_{r}\sum_{i,t\in r}\ell_{i,t}}
{\sum_{r}\sum_{i,t\in r}m_{i,t}}.
$$

这里 $r$ 是 data-parallel rank。附加的 KL 或 entropy 项也要说明自己的归一化分母；不能只修正 policy loss 而让 KL 在多卡上悄悄乘上 `world_size`。

## 26.3 四种并行分别传什么

**DP：** 每张卡有不同样本；反向后对同一参数的梯度做 all-reduce 或 reduce-scatter。它解决“样本分片”，不是层内矩阵乘法。

**TP：** 一个线性层的权重或 head 被切片；前向需要 all-gather/all-reduce，中间结果的通信是数学计算的一部分。

**PP：** 不同层放在不同卡；前向发送 activation，反向发送 activation gradient。micro-batch 太少会出现 pipeline bubble。

**EP：** MoE router 选 expert，token 经 all-to-all 发到目标 expert；反向沿相反路径返回。EP 的 all-to-all 不应被误认为 DP 梯度同步。

可以画成一条数据路径：

```text
rollout workers: prompt -> response, reward, old_logp, version
trainer:         current policy forward -> ratio/KL/masked loss
DP:              reduce-scatter/all-reduce gradients
TP/EP:           layer collectives / expert all-to-all
PP:              activation send/recv
optimizer:       one global step -> publish versioned weights
```

## 26.4 权重同步的边界

训练器从版本 $v$ 更新到 $v+1$ 后，rollout 服务在**请求边界**原子切换。若在生成中途换权重，一条 response 会由两个 behavior policy segment 组成，原来的单一 `old_logp` 不再成立。常见同步方式有全量 broadcast、分片 all-gather、共享 checkpoint 和参数服务器；选择时要同时记录同步耗时与版本生效时间。

## 26.5 最小双 rank 实验

下面的伪代码展示“只归约分母一次”的思想。标准 PyTorch DDP 会在 rank 间**平均**梯度，因此 backward 前要乘回 `world_size`；否则会得到正确方向但缩小 $1/\text{world\_size}$ 的梯度：

```python
local_num = (token_loss * mask).sum()
local_den = mask.sum()
global_den = local_den.detach().clone()
dist.all_reduce(global_den, op=dist.ReduceOp.SUM)
reducer_scale = dist.get_world_size()  # standard DDP averages gradients
loss_for_backward = reducer_scale * local_num / global_den.clamp_min(1)
loss_for_backward.backward()
```

手算两张卡即可验证：DDP 最后平均两张卡的梯度，前面的 `reducer_scale=2` 正好抵消这次平均，留下 $(\nabla n_0+\nabla n_1)/(d_0+d_1)$。若你的 FSDP、自定义 reducer 或框架返回的是梯度**求和**而不是平均，就把 `reducer_scale` 设为 1；必须先查 reducer 契约，不能同时在 loss 和梯度 bucket 上各补一次倍数。若还使用 gradient accumulation，micro-batch 的缩放也要单独计入。

用两组不等长样本，分别测试：全局 token mean、local mean 再平均、错误地对 loss 做两次 all-reduce。比较 loss、每层梯度范数和最终参数差异，并把 `world_size`、reduction op、gradient accumulation steps 写入日志。

## 26.6 排错清单

1. 单卡与多卡 loss 相差 `world_size`：查 sum/mean 约定和重复归约。
2. reward 突然下降：核对 rollout 的 policy version、sampling warper、tokenizer、dtype 和 MoE route。
3. 某 rank 显存峰值异常：检查 PP micro-batch、EP capacity、参数 all-gather 时机。
4. NaN：先打印每 rank 的有效 token 数、advantage 范围、`old_logp` 是否为有限值，再查 mixed-precision scale。

**验收：** 你能解释为什么离散 rollout 不反传，手算 $8/10$，并在图上标出 DP、TP、PP、EP 的通信边界。
