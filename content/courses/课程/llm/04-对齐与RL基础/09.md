## 9.1 先看双卡上的“同样 loss，完全不同步长”

两张卡各有两个有效 token。卡 0 的 token loss 是 $(1,1)$，卡 1 的 token loss 是 $(3,3)$。正确的全局 token mean 是

$$
\frac{1+1+3+3}{4}=2.
$$

如果每张卡先求 local mean，得到 $1$ 和 $3$，再做一次跨卡平均，仍然得到 $2$，看起来没问题。可是如果一张卡只有一个有效 token，另一张卡有三个，先做“每卡 mean 再平均”就会把两个样本等权，而不是按 token 等权。更糟的是，loss 已经按 global mean 算过后又在可微图里做一次 `SUM`，梯度可能再放大 world size。

本章目标：分清日志归约、loss 数值归约和梯度归约；用一个两卡单层模型手算重复 `SUM`/`MEAN` 的梯度；建立不依赖猜测的最小单元测试。

## 9.2 三种通信先分开

**日志 all-reduce。** 只为了显示全局平均，把 `loss.detach()` 复制后通信，再打印。它不应进入反向图。

**loss 数值归约。** 把不同 rank 的分子、分母合成一个全局标量，随后这个标量参与 backward。它会影响梯度，必须定义清楚是 sum 还是 mean。

**梯度归约。** DDP/FSDP 在 backward 期间对梯度做 all-reduce 或 reduce-scatter。它和前向 loss 的归约是两件事，不能因为“梯度已经同步”就认为 loss 可以随便再平均。

## 9.3 为什么 token mean 要归约两个数

每个有效 token 的损失为 $\ell_{r,t}$，mask 为 $m_{r,t}$。全局目标是

$$
L_{\mathrm{global}}
=\frac{\sum_{r,t}m_{r,t}\ell_{r,t}}
{\sum_{r,t}m_{r,t}}.
$$

分子是所有有效 token loss 的和，分母是有效 token 数。若每个 rank 的 token 数不同，不能只平均各 rank 的 local mean。

两卡数字例子：

- 卡 0：一个 token，loss $0$；
- 卡 1：三个 token，loss 都是 $3$。

正确全局 mean 为

$$
L=\frac{0+3+3+3}{4}=2.25.
$$

先算 local mean 再平均得到 $(0+3)/2=1.5$，已经改变目标。若每条回答有不同长度，这个错误会系统性偏向短或长样本。

## 9.4 DDP 梯度为什么又有一个 world-size 因素

设每个 rank 都用**本地 mean**作为 loss，DDP 在 backward 后对各 rank 梯度做平均。若每个 rank 的样本量相同，本地 mean 的梯度平均等于全局样本 mean 的梯度，这很方便。

对本章稍后的“本地可微分子除以全局 detached 分母”写法，若 DDP 把 $W$ 个 rank 的梯度取平均，每个 rank 的 loss 需要乘 $W$，才能得到全局 token mean 的梯度；若框架把梯度求和，系数就是 $1$。如果使用 autograd-aware collective 直接构造全局可微 mean，collective 的 backward contract 又可能不同。FSDP 的 reduce-scatter、梯度累积和混合精度 scaler 也会改变细节，所以不要脱离具体写法背“必须乘 $W$”或“必须除 $W$”的口诀。

真正可靠的做法是：

1. 写出框架文档规定的 loss/gradient reduction contract；
2. 用一个线性层和手算梯度验证；
3. 固定 token 数与 rank 数后再引入变长 batch。

## 9.5 重复 all-reduce 的三种情况

**情况 A：detach 后重复日志归约。** 数值显示可能重复平均或重复求和，但没有改变模型梯度；只是日志错了。

**情况 B：普通原地 `all_reduce` 修改了带梯度的 tensor。** PyTorch 的分布式 collective 通常不是 autograd-aware。它可能改变前向数值、触发 in-place version error，或者让你以为梯度已按通信传播但实际没有。不能靠变量的 `requires_grad` 猜结果。

**情况 C：可微 collective 或归约结果参与后续计算。** 对一个已经是 global mean 的量再做可微 `SUM`，两 rank 时梯度约放大 $2$；重复一次再放大约 $2$。对可微 `MEAN` 则约缩小 $2$。实际比例取决于 API 的 sum/mean 语义和 DDP 后续归约。

## 9.6 一个单参数的手算

模型输出 $z=\theta x$，每个样本的平方损失为 $\ell=(z-y)^2$。两 rank 各一个样本：

- rank 0：$x=1,y=0$，当 $\theta=1$ 时 loss 为 $1$，梯度为 $2$；
- rank 1：$x=1,y=2$，loss 为 $1$，梯度为 $-2$。

正确 global mean loss 为 $1$，global mean gradient 为

$$
\frac{2+(-2)}2=0.
$$

如果先把两个 loss 可微 `SUM` 成 $2$，再把这个相同的 sum 在两卡都用于 backward，得到的梯度约为 $2+(-2)=0$，这个例子恰好看不出缩放；所以测试必须选不抵消的梯度。改成 rank 1 的目标 $y=1$，其梯度为 $0$：正确 mean gradient 是 $1$，可微 sum 得到约 $2$，重复一次约 $4$。这就是为什么用“最终 reward 没变”无法诊断 loss scaling。

## 9.7 概念上安全的 token-mean 写法

```python
local_num = (token_loss * response_mask).sum()
local_den = response_mask.sum()

# 只把分母复制后做通信；分子保持本 rank 的计算图。
global_den = all_reduce_sum(local_den.detach())
loss = local_num / global_den.clamp_min(1)

# 下面的缩放必须按 DDP/FSDP 文档确认，不能假定是 world_size。
loss = loss * reducer_scale
loss.backward()
```

日志版本另写：

```python
log_num = local_num.detach().clone()
log_den = local_den.detach().clone()
all_reduce_sum(log_num)
all_reduce_sum(log_den)
logger.log({"global_token_loss": log_num / log_den.clamp_min(1)})
```

对上面这段“local numerator / global detached denominator”的精确写法，若 DDP 平均梯度，则 `reducer_scale` 应为 `world_size`；若框架求和梯度，则应为 $1$。梯度累积、FSDP reduce-scatter 和 autograd-aware collective 可能采用其他 contract。把它当成必须用单卡参考梯度验证的接口变量，而不是通用常数。

## 9.8 训练中常见的隐蔽放大

- local loss 已经按 token mean，外层 trainer 又除一次全局 token 数；
- gradient accumulation 每个 microbatch 都平均，最后又按总 token 数平均，导致长短 batch 权重不一致；
- DDP 以 sample mean 归约，但 RL loss 实际想按 token mean；
- KL、entropy 和 policy loss 使用不同 denominator，改变相对系数；
- AMP loss scaler 看到错误放大的 loss，造成溢出或过度缩小。

## 9.9 项目实验与完成标准

用两张卡或两个模拟 rank 的线性层，测试以下组合：本地 sample mean、全局 token mean、重复 `SUM`、重复 `MEAN`、日志 detach、autograd-aware collective。每种组合都与单卡拼接 batch 的参考梯度比较，误差阈值设为 $10^{-6}$（确定性 FP32 情况）。

记录：梯度范数、梯度比值、optimizer step 后参数差、AMP overflow 次数。完成标准是你能用一个最小测试指出“loss 变了但梯度没变”“梯度乘了 world size”“只是日志重复归约”三种情况，而不是凭经验猜。
