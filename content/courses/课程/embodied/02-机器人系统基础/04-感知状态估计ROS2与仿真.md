# M2.4 主干：感知、状态估计、ROS2 与仿真

## 学习目标

学完本章，你应能把原始传感器变成带时间戳和坐标系的状态估计，理解 ROS2 节点通信和 TF，区分物理仿真与渲染，并设计一个不会因同步或接口错误而失真的训练循环。

## 7.1 从测量到任务状态

感知流水线通常包含：

```text
原始信号 -> 标定/去畸变 -> 特征或检测 -> 坐标变换
        -> 多帧关联 -> 状态估计 -> 任务表示
```

任务表示可能是：物体类别与 6D 位姿、点云、占据栅格、语义地图、目标与障碍物集合，或直接供端到端策略使用的视觉特征。

端到端不等于没有中间状态。模型内部仍会形成表示，只是它未必可解释，也未必带显式几何约束。

## 7.2 几类感知任务

- 分类：图中主要对象是什么。
- 检测：对象类别和二维框。
- 分割：每个像素属于什么。
- 深度估计：每像素距离。
- 6D 位姿：物体三维位置和旋转。
- 跟踪：跨时间维持对象身份和运动状态。
- 可供性：对象哪里可抓、可按、可放。

操作任务往往需要厘米甚至毫米级几何。分类准确并不意味着抓取点准确。

## 7.3 相机标定与点云

像素和深度可通过相机内参反投影：

$$
\begin{aligned}
X &= \frac{(u-c_x)Z}{f_x},\\
Y &= \frac{(v-c_y)Z}{f_y},\\
Z &= D(u,v).
\end{aligned}
$$

得到的是相机坐标，再用 ${}^{\mathrm{base}}T_{\mathrm{camera}}$ 变到机器人基座。深度图中的 0、NaN、边缘噪声和透明物体必须显式处理。

点云是无序点集合。常见处理包括体素下采样、离群点去除、法向估计、配准和分割。下采样节省计算但可能抹掉小物体或薄结构。

## 7.4 状态估计与部分可观测

真实状态无法直接读取，状态估计器维护信念：

```text
prediction:  根据上一状态和动作预测当前状态
update:      用新测量修正预测
```

线性高斯系统可用 Kalman filter；非线性系统常用 EKF/UKF；复杂多峰问题可用粒子滤波。关键不在背算法名，而在理解：

- 过程噪声表示动力学预测的不确定性。
- 测量噪声表示传感器的不确定性。
- 协方差决定更信预测还是更信测量。

如果单帧观测不足以判断状态，问题是 POMDP。可通过多帧堆叠、RNN/Transformer 记忆、显式滤波器或主动感知缓解。

## 7.5 视觉伺服

视觉伺服直接用图像特征误差闭环控制机器人：

- IBVS：在图像平面定义误差，通常对标定误差更鲁棒。
- PBVS：先估计三维位姿，再在三维空间控制，路径直观但依赖位姿估计。

视觉更新慢、延迟大，低层控制仍需更高频。遮挡和目标丢失必须进入状态机，而不是继续使用过期目标。

## 7.6 ROS2 基本图模型

ROS2 用节点组织模块：

- Topic：持续发布的数据流，如相机、关节状态。
- Service：短请求/响应，如读取配置。
- Action：可反馈、可取消的长任务，如移动到目标。
- Parameter：节点配置。
- TF2：维护带时间的坐标变换树。
- rosbag2：记录和回放消息。

Topic 不是共享内存变量。发布频率、QoS、队列深度和时间戳会影响接收结果。

## 7.7 QoS、时间与 TF

相机流可接受丢帧但不能积压旧帧；控制命令通常要求低延迟和可靠边界。ROS2 QoS 需要按数据语义选择 reliability、durability、history 和 depth。

TF 查询必须在传感器测量时刻进行。如果用“当前机械臂位姿”变换 200 ms 前拍摄的图像，移动中会产生系统性空间误差。

推荐每条接口记录：

```text
消息类型、单位、坐标系、时间戳来源、发布频率、最大容忍延迟、QoS
```

## 7.8 实时边界

ROS2 和 Python 适合高层协调，但不应默认承担硬实时电流环。常见分层：

```text
1-10 Hz   任务规划/VLM
10-50 Hz  视觉策略/动作块更新
100-1000 Hz 关节伺服/状态估计
更高频    电机驱动器内部电流环
```

频率只是示例，不是标准答案。最终取决于机器人、任务和硬件。

## 7.9 仿真器解决什么

仿真器至少包含：

- 动力学积分与接触求解；
- 关节、执行器、传感器模型；
- 碰撞几何；
- 可选渲染、场景和数据生成；
- 环境重置与并行接口。

| 工具 | 强项 | 典型用途 |
|---|---|---|
| MuJoCo/MJX | 接触动力学、模型简洁、研究生态 | 控制、操作、RL |
| Isaac Sim/Lab | GPU 并行、传感器与渲染、机器人资产 | 大规模 RL、合成数据 |
| Gazebo | ROS 系统集成、传感器插件 | 系统工程与导航 |
| PyBullet | 易上手、原型快 | 教学和轻量实验 |

版本和任务决定实际选择，不能只按热度。仿真快不代表物理准，渲染真实也不代表接触准确。

## 7.10 仿真时间步和控制步

物理步长可能是 1 ms，控制器每 10 个物理步更新一次，策略每 5 个控制步更新一次。必须区分：

```text
physics_dt
control_decimation
policy_update_interval
episode_horizon
```

改变其中一个会同时改变稳定性、数据频率和任务时长。训练数据中的 fps 也必须与部署执行语义一致。
