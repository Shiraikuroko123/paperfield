# M3.4 专题：模仿学习主线 BC → DAgger → ACT

> 锚点论文：ACT（"Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware"，ALOHA 项目，Zhao et al., 2023）

## 一、为什么操作任务选了模仿学习这条路

RL 在运动控制上大杀四方（M3.2 RL 与运动控制专题），但在操作任务上卡住了：奖励怎么设计？"叠好衣服"的奖励函数写不出来；稀疏奖励（成功=1）又让探索几乎不可能命中。而模仿学习绕开奖励设计：**人做给机器看，机器直接学映射**。代价是要采数据——这个代价塑造了之后整个领域的格局（M4.3 数据问题专题）。

## 二、Behavior Cloning：最简形式与致命伤

BC 是监督学习：在数据集 $\mathcal{D}=\{(o_i,a_i)\}_{i=1}^{N}$ 上训练 $\pi_\theta(a\mid o)$ 拟合专家动作，其常见目标为

$$
\min_\theta\;\mathbb{E}_{(o,a)\sim\mathcal{D}}
\left[-\log\pi_\theta(a\mid o)\right].
$$

**致命伤：复合误差（compounding error）。** 训练数据只覆盖专家走过的状态。策略执行时每步有小误差，误差把机器人带到专家没去过的状态，模型没见过 → 更大误差 → 滚雪球偏出数据分布。学术名：**covariate shift**（训练与执行的状态分布不一致）。

**DAgger 的解法**：执行当前策略收集新状态，请专家在这些状态上标注正确动作，加入数据集重训，迭代。理论优雅，实践尴尬——每轮都要专家在线陪跑，人类受不了。所以工业界的实际答案是：**多采数据+让模型更能扛误差**，ACT 是后者的代表。

## 三、ACT：怎么把 BC 做到能穿扎带、装电池

ALOHA 团队用约 2 万美元的双臂遥操作台采数据，每个任务只要 **50 条示范**，就能在精细任务（穿扎带、开半透明调料杯、装电池）上做到 80-90% 成功率。三个关键设计：

**1. 动作分块（Action Chunking）——名字里的 AC**
不只预测下一步动作，而是一次预测未来 $k$ 步（原论文常用 $k=100$）动作序列。这样能学习连贯动作片段，并减少逐步动作噪声。是否减少推理次数取决于执行协议：ACT 配合时间集成时可在每个控制步重新预测 chunk；只有整块开环执行时，推理次数才会明显下降，但反应性也更差。动作分块缓解复合误差，并没有按 $k$ 倍消除它。

**2. 时间集成（Temporal Ensembling）**
每个时刻其实有多个历史 chunk 都对当前步有预测，用指数加权平均合并，避免 chunk 切换时的抖动。若 $\hat a_t^{(i)}$ 表示第 $i$ 个历史 chunk 对时刻 $t$ 的预测，则

$$
a_t=
\frac{\sum_i \exp(-\lambda i)\,\hat a_t^{(i)}}
{\sum_i \exp(-\lambda i)}.
$$

**3. CVAE 结构——名字里的 T 是 Transformer**
人类示范有随机性（同一任务每次做法略不同），直接回归会学成"平均动作"（可能是错的）。ACT 用条件变分自编码器：编码器把示范压成风格变量 $z$，解码器（Transformer）以图像、关节状态和 $z$ 为条件输出动作块。推理时 $z$ 取零向量，输出"平均风格"但连贯的动作。

**架构一句话**：多相机图像过 ResNet → 与关节状态、$z$ 一起进 Transformer encoder-decoder → 输出 $k\times d_a$ 的动作序列。参数量约 80M，单卡几小时可训——这就是你 12 月复现它的原因。

## 四、批判（复试杀手锏）

1. **仍是 BC**：没见过的状态照样崩，50 条示范的覆盖极有限；换物体位置、换光照就可能失效
2. **CVAE 对多模态的处理偏弱**：z 取零丢掉了真正的多模态性 → 这正是 M3.5 Diffusion Policy 的切入点
3. **无语言、单任务**：一个任务训一个模型，谈不上通用 → VLA 的切入点
4. **长 chunk 与时间集成是双刃剑**：预测范围和融合过强会平滑动作，也可能增加滞后；实际反应性取决于重预测频率、执行步数和融合权重

## 五、复试级问答

**Q1：BC 的复合误差为什么会发生？ACT 用什么缓解？**
要点：训练分布≠执行分布（covariate shift），小误差把状态带出示范覆盖 → 雪球。ACT 用动作分块减少决策次数、时间集成平滑衔接；本质是"少犯错+错了别抖"，并没有真正解决分布外问题。

**Q2：DAgger 理论上解决了 covariate shift，为什么实际很少用？**
要点：需要专家对策略访问到的状态在线标注，人类专家成本极高且难以在机器人失控状态下给出"正确动作"；工业实践转向大规模离线示范 + 更鲁棒的架构。

**Q3：为什么 ACT 用 CVAE 而不是直接回归？如果去掉 z 会怎样？**
要点：示范存在多种做法，直接 $L_1/L_2$ 回归会得到某个点统计量（可能无效，比如绕障碍左右两条路的折中是撞上去）。$z$ 捕捉风格让训练目标一致化。去掉 $z$（论文消融）成功率明显下降。追问预备：这个问题更彻底的解法是生成式策略——Diffusion Policy。

## 工程视角附录

**核心伪代码**（对照第三节看）：

```python
# ===== 训练（CVAE）=====
for imgs, qpos, a_chunk in loader:            # a_chunk: 未来 k=100 步动作
    mu, std = cvae_encoder(qpos, a_chunk)     # 编码器只在训练时存在
    z = mu + std * randn()                    # 重参数化
    a_pred = transformer(resnet(imgs), qpos, z)
    loss = reconstruction_loss(a_pred, a_chunk)
    loss += kl_weight * kl_divergence(mu, std)

# ===== 推理 =====
z = zeros()                                   # z 取零向量
每 1 步都预测新 chunk，对时刻 t 的所有历史预测做时间集成：
a_t = temporal_ensemble(chunks, decay=0.01)
```

**真实超参**：chunk_size 100 / batch 8 / lr 1e-5 / kl_weight 10 / 训练 8-10 万步；4090 上约 3-5 小时，这就是"十几块钱训一次"的出处。

**常见坑**：
1. 归一化统计（动作/状态的 mean、std）必须来自训练集且推理时一致——LeRobot 存在 `stats` 里，换数据集忘换统计 = 静默灾难
2. 多相机的 key 名（`observation.images.cam_high` 等）对不上不报错，只是学不会
3. 时间集成关掉→动作抖，权重太强→反应钝，m 值可调
4. 评测方差极大：每个 checkpoint 至少 50 次 rollout 再下结论（M6.2 评测危机专题伏笔）
