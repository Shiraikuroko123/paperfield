# M3.6 专题：π0 与 flow matching 动作头

> 锚点：π0（Physical Intelligence, 2024）、π0.5（2025）；前置：第 03、05 课

## 一、π0 是谁、为什么值得单独一课

Physical Intelligence（π）：Sergey Levine、Chelsea Finn 等人创办的创业公司，融资数十亿美元，只做一件事——**机器人基础模型**。π0 是他们的第一代旗舰，代表当前 VLA 的完成度天花板：叠衣服（软物体+长时序的双料噩梦）、收拾餐桌、组装纸箱，且开源了代码与权重（openpi 仓库）——所以它既是你要懂的前沿，也是你可能亲手跑的模型。

## 二、架构：VLM 底座 + 动作专家

```
图像+指令 → PaliGemma VLM (3B) ──┐
                                  ├→ 动作专家 (~300M, flow matching)
本体状态 ─────────────────────────┘         ↓
                            50Hz 连续动作块（未来 ~1 秒）
```

关键设计：**语义归 VLM，动作归专家**。VLM 部分继承互联网知识（RT-2 的遗产），动作专家用 flow matching 生成高频连续动作（Diffusion Policy 的遗产提速版）。两者拼接训练。这个"底座+动作头"的分工已成为 2026 年 VLA 的标准板式（GR00T 同款思路，M4.6 跨本体专题）。

## 三、flow matching 三分钟版

扩散模型：学"怎么一步步去噪"，推理要几十步。
Flow matching：直接学**一个速度场**，把噪声点沿近似直线"流"到数据点。训练同样是简单回归（预测速度向量），但概率路径更直 → **推理几步就够**。

对机器人意味着什么：$50\,\mathrm{Hz}$ 控制频率成为可能（扩散策略难以做到），同时保留生成式策略的多模态表达力。一句话给考官：**flow matching = Diffusion Policy 的表达力 + 接近单步推理的速度。**

## 四、训练配方（比架构更值得学）

π0 的真正护城河是配方，注意每一步都呼应前面课程：

1. **预训练**：约 1 万小时、多平台（单臂/双臂/移动操作）自采+OXE 数据混训 → 学"广而糙"的通用操作先验（数据金字塔中下层）
2. **后训练（post-training）**：对目标任务用小量高质量精选示范微调 → "专而精"
3. π0.5 的升级：**开放世界泛化**——训练混入网页数据、高层子任务预测（先输出"该拿起盘子"再输出动作），能进**没见过的家庭**做清洁。分层的快慢思想（M4.7 LLM Agent 专题钩子）

"预训练学广、后训练学精"直接类比 LLM 的 pretrain→SFT，这个类比在复试里讲出来非常加分。

## 五、批判（复试杀手锏）

1. **评测自家说了算**：任务、场景、指标全是 π 自定义，没有公共 benchmark 可横向比较（M6.2 评测危机专题的活案例）
2. **仍是 BC 天花板**：1 万小时也只是"示范分布内"，错误恢复能力有限；叠衣服 demo 惊艳但成功率和速度距商用有距离
3. **算力门槛**：预训练非学界可复现，学界只能做后训练/微调层面的研究——认清这点能帮你选题
4. **跨本体仍靠"数据里见过"**：没见过的机器人形态还是不行（M4.6 跨本体专题主题）

## 六、复试级问答

**Q1：π0 为什么用 flow matching 而不是扩散或自回归 token？**
要点：三选项对比——自回归离散 token：慢+精度损失；扩散：表达力强但迭代去噪慢；flow matching：表达力相当+概率路径直+推理步数少 → 满足 50Hz 高频控制。本质权衡是**表达力 vs 控制频率**。

**Q2：π0 的"预训练+后训练"和 LLM 的"pretrain+SFT"类比，哪里成立哪里不成立？**
要点：成立——都是"大杂数据学先验、小精数据对齐行为"。不成立——LLM 预训练数据免费且万亿级，π0 预训练数据自采且仅万小时级，所以机器人的"预训练"远没到 scaling 饱和，数据仍是主约束；且 LLM 的 RLHF 环节在机器人上尚无对应物（真机 RL 太贵）。答出不成立的部分才显功力。

**Q3：开源的 openpi 你能用它做什么研究（没有大算力的前提下）？**
要点：①在 LIBERO 等仿真 benchmark 上微调+评测，研究微调数据配比/LoRA 策略；②分析动作头行为（多模态性、失败模式归类）；③蒸馏小模型。核心逻辑：**底座别人训好了，研究"怎么用好底座"恰是单卡能做且顶会在收的方向**。

## 工程视角附录

**flow matching 核心伪代码**（和M3.5 Diffusion Policy 专题扩散版对照着看，差异一目了然）：

```python
# ===== 训练 =====
t = rand()                                   # t ∈ [0,1]
a_t = interpolate(noise, a0, t)              # 直线插值
target_velocity = a0 - noise
loss = mse_loss(model(a_t, t, vlm_feat, qpos), target_velocity)

# ===== 推理（10 步 Euler 积分，扩散要几十步）=====
a = noise
for t in linspace(0, 1, 10):
    a = a + model(a, t, obs) * (1/10)
# 得到 50 步动作块 @50Hz
```

对应的训练路径、速度目标和损失分别为

$$
\begin{aligned}
a_t &= (1-t)\epsilon+t a_0,\\
u_t &= a_0-\epsilon,\\
\mathcal{L}_{\mathrm{FM}}(\theta)
&=\mathbb{E}_{a_0,\epsilon,t}
\left[\left\lVert v_\theta(a_t,t,o)-u_t\right\rVert_2^2\right].
\end{aligned}
$$

推理时求解常微分方程 $\mathrm{d}a/\mathrm{d}t=v_\theta(a,t,o)$；上面的循环使用 Euler 离散化。

**仓库导读**（`Physical-Intelligence/openpi`）：架构是"策略服务器"模式——策略进程起 websocket server，机器人端 client 请求动作；归一化统计 norm_stats 跟着 checkpoint 走；每种机器人一个 config（声明相机数、动作维度）。

**常见坑**：
1. π0 是底座不是成品：对你的新任务 zero-shot 基本不行，**必须微调**——预期管理
2. JAX 原版环境难装，社区 PyTorch 移植版对新手友好得多
3. 动作维度按 config 自动 padding 到统一宽度，别手动改维度
4. 推理显存约 8-10G——4060 笔记本挤得进，这是你能亲手跑 π0 的依据
