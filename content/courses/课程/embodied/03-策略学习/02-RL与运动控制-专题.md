# M3.2 专题：RL 与运动控制

> 锚点论文：Legged Gym（"Learning to Walk in Minutes Using Massively Parallel Deep RL"，Rudin et al., 2022）；延伸：RMA、Humanoid-Gym

## 一、为什么运动控制是 RL 的主场（而操作不是）

对比M3.4 BC 到 ACT 专题的逻辑，运动控制恰好避开了 RL 的所有短板：

| 条件 | 运动控制 | 操作任务 |
|---|---|---|
| 奖励好写吗 | 好写：速度跟踪+别摔倒 | 难写："叠好衣服"无法形式化 |
| 仿真准吗 | 刚体+地面接触，较准 | 抓握接触、软物体，很难准 |
| 试错代价 | 仿真里摔一亿次免费 | 真机摔=损坏 |

所以领域分工形成：**腿用 RL 在仿真里练，手用模仿学习在真机上教。** 这句话是理解具身智能格局的钥匙。

## 二、PPO：够用就好的主力算法

领域 95% 的运动控制工作用 PPO。直觉版原理：策略梯度=朝着"高回报动作概率增大"的方向更新；PPO 的贡献是给每次更新加"裁剪"（clip），防止一步更新走太远导致崩盘。**on-policy**（只用当前策略采的数据）、稳定、超参不敏感、天然适合大规模并行采样——这是它统治的原因，不是因为它样本效率高（恰恰相反）。

样本效率低怎么办？**用吞吐量硬灌**：Isaac Gym/Isaac Lab 在单张 GPU 上并行跑 4096 个仿真环境，物理仿真和神经网络全在 GPU 上不搬运数据 → 四足行走 20 分钟训完。"Walk in minutes" 改变了整个领域的迭代速度。

## 三、真正的手艺：奖励塑形与域随机化

**奖励塑形（reward shaping）**——策略好坏 70% 取决于此，典型配方：

$$
r_t=
w_v r_{\mathrm{track}}
+w_s r_{\mathrm{alive}}
-w_\tau\lVert\tau_t\rVert_2^2
-w_a\lVert a_t-a_{t-1}\rVert_2^2
-w_l r_{\mathrm{limit}}
-w_d r_{\mathrm{drag}}
+w_h r_{\mathrm{foot\ height}}.
$$

每一项系数都要调。这就是"炼丹"的真实含义，也是这条路线被诟病"不优雅"的原因。

**域随机化（Domain Randomization, DR）**——Sim2Real 的第一支柱：训练时随机化质量、摩擦、电机强度、通信延迟，并随机推搡机器人。逻辑：真实世界只是"随机化分布中的一个样本"，见过千奇百怪的仿真就不怕一个真实。代价：策略变保守（为鲁棒牺牲最优）。

**RMA / Teacher-Student**——优雅升级：老师策略在仿真里可以看"特权信息"（真实摩擦系数等），学得又快又好；学生策略只用真机可得的本体感受历史，蒸馏模仿老师，并**从历史中隐式推断环境参数**。这是"从历史推断世界"思想的源头，后续大量工作沿用。

**人形的额外难度**（Humanoid-Gym 等）：接触点少、重心高、自由度多，奖励里要加对称性、步态周期等先验；zero-shot sim2real 已在多款人形上验证。

## 四、批判（复试杀手锏）

1. **奖励工程不可扩展**：每个新技能重新炼丹，与"通用智能"背道而驰 → 动机引出模仿人类动作（motion tracking，M5.3 人形全身控制专题）
2. **DR 是钝器**：随机化范围本身要调；范围太大学不会，太小过不去 Sim2Real
3. **盲走为主**：纯本体感受策略看不见台阶，感知式行走（升高图/视觉）仍在攻坚
4. **RL 的成功没有迁移到操作**：接触丰富、目标多样的任务里，纯 RL 至今没有规模化成功——承认这一点显得你清醒

## 五、复试级问答

**Q1：为什么运动控制用 RL、操作用模仿学习？**
要点：奖励可写性、仿真保真度、试错代价三个维度对比（背上面的表）。加分句：本质是"监督信号从哪来"的问题——运动的监督信号可以从物理仿真里免费挖，操作的监督信号目前只能从人身上挖。

**Q2：域随机化为什么能过 Sim2Real？代价是什么？**
要点：把真实世界视为随机化分布的一个样本，训练覆盖它。代价：保守性（牺牲最优性换鲁棒性）+ 随机化范围本身成为新超参。升级方案：RMA 式在线适应——不是对所有环境都用一个保守策略，而是从历史推断当前环境再适应。

**Q3：PPO 样本效率不高，为什么运动控制领域还都用它？**
要点：因为瓶颈不在样本效率而在墙钟时间——GPU 并行仿真让样本几乎免费，此时算法稳定性、超参鲁棒性比样本效率值钱。反例对照：真机 RL 才需要样本高效算法（off-policy SAC 等）。答出"算法选择取决于数据获取成本结构"即满分。

## 工程视角附录

**奖励函数的真实样子**（legged_gym 风格——每项一个函数，框架自动按 scale 加权求和）：

```python
def _reward_tracking_lin_vel(self):     # 主项：速度跟踪
    error = self.commands[:, :2] - self.base_lin_vel[:, :2]
    return torch.exp(-torch.sum(error**2, dim=1) / 0.25)
def _reward_torques(self):              # 省电
    return -torch.sum(self.torques**2, dim=1)
def _reward_action_rate(self):          # 平滑
    return -torch.sum((self.actions - self.last_actions)**2, dim=1)
def _reward_feet_air_time(self):        # 鼓励迈大步（治小碎步）
    return torch.sum(self.feet_air_time - 0.5, dim=1)  # 触地时结算
# reward_scales = {tracking: 1.0, torques: -1e-5, action_rate: -0.01, ...}
```

**PPO 主循环结构**：4096 环境并行 → 每环境 rollout 24 步 → GAE 算优势 → 5 个 epoch 小批量更新 → 循环。全程数据不出 GPU。

**域随机化典型范围**：摩擦 0.5-1.25 / 连杆质量 ±10% / 每 10s 随机推一把（1m/s）/ 控制延迟 0-40ms / 电机强度 ±10%。

**仓库导读**：`leggedrobotics/legged_gym`（经典，代码量小先读这个，`legged_robot.py` 里搜 `_reward_`）→ IsaacLab（现役，奖励在 `envs/**/mdp/rewards.py`）。

**常见坑**：
1. 奖励量级失衡是第一死因：先只开"跟踪+存活"训通，再逐项加惩罚
2. "站桩"局部最优：机器人学会站着不动骗存活奖励——用 feet_air_time 和命令课程逼它走
3. 观测里混入仿真特权量（真实速度、接触力）→ 真机没有这些传感器，必挂
4. action scale 和 PD 增益强耦合，改一个必须重调另一个
