# M4.4 主干：VLM、VLA、跨本体与具身 Agent

> 前沿状态日期：2026-07。模型名称和仓库接口会变化；稳定概念、原始资料与时效性判断分开阅读。

## 学习目标

学完本章，你应能解释互联网预训练如何进入机器人策略，拆解 VLA 的视觉、语言、状态和动作模块，比较动作表示和快慢系统，理解跨本体对齐与 grounding，并给出部署和评测方案。

## 12.1 从 VLM 到 VLA

VLM 学习图像与语言的联合表示，可提供对象、属性、关系和常识先验。VLA 在此基础上加入机器人状态和动作建模：

```text
input: images + language + proprioception + history
model: visual encoder/VLM + fusion + action head
output: action token, continuous action, or action chunk
```

互联网预训练能帮助理解“红杯子”“易碎”“放进抽屉”等语义，但不会自动提供毫米级控制、机器人坐标和接触动力学。这些仍来自机器人数据、仿真和控制结构。

## 12.2 三类动作表示

### 离散动作 token

把归一化连续动作量化到 bin，再使用语言模型式自回归输出。优点是复用 VLM/LLM 架构；代价是量化误差、逐 token 延迟和词表/动作语义耦合。

### 连续回归或 mixture

一次前向输出动作或分布参数，快且易部署；简单点回归处理多峰动作有限。

### 生成式连续动作头

Diffusion Transformer 或 flow matching 生成动作块，兼顾连续精度和多模态分布；需要数值采样和专门动作模块。

选择应基于精度、频率、任务多模态、硬件和训练数据，而不是追随单一架构潮流。

## 12.3 训练阶段

常见但不统一的配方：

1. 视觉/语言预训练：学习语义与表示。
2. 多机器人预训练：学习通用操作先验。
3. 目标本体适配：对齐相机、状态和动作空间。
4. 目标任务后训练：用高质量示范提升精度。
5. 可选 RL/偏好/价值优化：改善成功、恢复或筛选。

机器人“预训练”的规模、质量和覆盖与文本预训练不可直接类比。是否存在稳定 scaling law 必须用控制数据与算力的实验验证。

## 12.4 代表性技术路线

以下只作为架构谱系，不用公司自报 demo 代替公共评测：

- RT 系列：多任务机器人数据与视觉语言预训练结合，动作 token 化。
- OpenVLA：开放权重和训练配方，便于研究微调与公共评测。
- π 系列：VLM 语义底座与连续生成式动作专家结合。
- GR00T 等快慢系统：高层视觉语言推理与低层高频动作模块分工。
- RDT 等扩散 Transformer：以连续动作生成和异构数据对齐为重点。

具体参数、频率和领先结论必须查对应版本的技术报告、代码和第三方评测。

## 12.5 快慢双系统

```text
慢系统：任务理解、语言推理、子目标，约低频更新
快系统：视觉运动策略、动作块或控制目标，中高频更新
低层控制：伺服与安全，高频运行
```

优点：计算职责匹配、模块可调试、长任务易重规划。代价：接口可能成为信息瓶颈，错误可能来自目标语义漂移或完成条件不一致。

“快系统输出 120 Hz 动作”可能只指动作执行采样率，不一定表示大网络完整推理 120 次/秒。论文阅读必须查清服务器推理、动作块长度和低层插值。

## 12.6 Cross-embodiment

跨本体面临三重异构：

- 观测：相机数量、位置和传感器不同；
- 动作：自由度、控制模式和语义不同；
- 动力学：质量、速度、回差和接触不同。

常见方法：

1. 每本体独立输入/输出 adapter，中间表示共享。
2. 统一动作槽位加 mask。
3. 使用末端位姿、关键点或语言子任务作为中间接口。
4. 形态 token/图结构显式描述本体。
5. 共享底座后对目标机器人微调。

目前“共享底座”通常比“零样本换身体”更现实。评测应分开 seen embodiment、new instance 和 truly unseen morphology。

## 12.7 Grounding 与具身 Agent

语言模型知道“清理洒出的水”可能需要海绵，但不知道当前机器人够不够得到、海绵在哪里、夹爪是否空闲。Grounding 是把语言计划约束到当前可观测和可执行的物理状态。

典型分层打分思想是从技能集合 $\mathcal{K}$ 中选择

$$
k^*=\arg\max_{k\in\mathcal{K}}
s_{\mathrm{lang}}(k\mid l,o)\,
s_{\mathrm{feasible}}(k\mid x),
$$

即同时考虑语言相关性与当前物理状态下的可行性。

现代系统还会加入：视觉状态、技能成功预测、执行反馈、记忆、异常检测和闭环重规划。

LLM Agent 调用 API 与机器人执行技能不同：物理状态部分可观测、动作概率成功、时间持续流逝、错误可能造成损坏。因此必须有监控、恢复和安全层。

## 12.8 记忆与长时序

长任务需要记住：已经完成什么、对象在哪里、哪些尝试失败、当前持有什么。可选机制：

- 滑动窗口多帧；
- RNN/Transformer 隐状态；
- 显式对象/事件记忆；
- 语言化执行日志；
- 世界模型或状态图。

记忆增加上下文，也会累积错误和旧信息。必须定义更新、遗忘和冲突解决策略。

## 12.9 部署架构

```text
机器人客户端
  -> 采集并时间对齐观测
  -> 请求策略服务器
策略服务器
  -> 预处理/模型推理/反归一化
  -> 返回带有效期的动作块
机器人客户端
  -> 安全检查/缓冲/低层执行
  -> 超时、丢包或异常则进入安全状态
```

需要测量端到端 P50/P95/P99 延迟、吞吐、显存、动作过期率和网络中断行为。平均推理速度不能代表实时可靠性。

## 12.10 研究与评测问题

- 收益来自架构、更多数据还是更大预训练模型？
- 语言改写、背景、相机、对象实例和布局分别如何泛化？
- 多本体数据是否造成负迁移？
- 生成动作是否在重规划间模式跳变？
- 模型能否识别失败并主动恢复？
- 延迟、安全过滤和低层控制对最终成功各贡献多少？

公共仿真 benchmark 适合可复现对比，真机适合验证现实效度；二者都需要失败分类和统计不确定性。

## 12.11 章节实践

为“陌生厨房中把指定杯子放进水槽”设计系统，明确：

- 高层/低层接口；
- 观测和动作表示；
- 训练数据；
- 完成检测；
- 三种恢复路径；
- 延迟与安全边界；
- seen/unseen 条件和评测次数。
