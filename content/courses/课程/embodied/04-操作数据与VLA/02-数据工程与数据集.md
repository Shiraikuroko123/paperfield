# M4.2 主干：机器人数据工程与数据集

## 学习目标

学完本章，你应能定义轨迹数据 schema，理解遥操作、仿真和视频数据的监督差异，检查同步、归一化、泄漏和质量问题，并设计带版本和许可证记录的数据流水线。

## 11.1 数据单位不能混比

文本使用 token，视频使用帧或小时，机器人数据使用 transition、episode 或小时。不同单位不能直接用“差几个数量级”推导能力差距。

比较数据规模时至少报告：

- episode 数和总控制步数；
- 总小时、采样频率和有效动作时长；
- 任务、对象、场景、本体和操作者多样性；
- 成功、失败、恢复和空闲比例；
- 观测与动作模态。

一百万条高度重复短轨迹，未必比十万条覆盖长尾和恢复的轨迹更有价值。

## 11.2 轨迹 schema

每个时间步通常包含：

```text
episode_id
timestamp
observations: images, joint_state, base_state, force, tactile, ...
action: representation, unit, reference_frame
task/language
done/success/failure/intervention
calibration and embodiment metadata
```

数据 schema 是训练接口合同。任何字段都必须写明形状、dtype、单位、坐标系、频率、缺失值规则和版本。

## 11.3 动作标签的语义

“7 维动作”可能是：

- 末端绝对位姿；
- 末端增量位姿；
- 关节位置；
- 关节增量；
- 速度或力矩；
- 6D 运动 + 1D 夹爪。

旋转又可能是欧拉角、轴角或四元数。训练 loss 正常下降不能证明语义映射正确；部署前应在仿真或可视化中回放动作。

## 11.4 数据来源

### 真机遥操作

优点是动力学和传感器真实；缺点是成本、重置、操作者差异和安全。常见设备包括主从机械臂、VR、手持夹爪、手套和人形遥操作。

### 仿真

容易生成状态真值、失败和长尾扰动，适合 RL 和数据增广；主要风险是物理、视觉和场景差距。

### 人类视频

语义和交互多样，但缺少机器人动作标签、视角/身体不同。适合学习表征、可供性、任务分解和潜在动作先验；直接得到可执行关节动作仍需要映射与对齐。

### 部署日志

能覆盖真实失败和用户分布，但涉及隐私、选择偏差、自动标注和安全回传。部署飞轮必须先解决可靠性，不能假定“上岗后自然有好数据”。

## 11.5 同步与切片

相机、关节和命令常不同频。建议保留原始时间戳，再生成明确版本的对齐数据：

1. 选择目标时间轴；
2. 连续状态插值；
3. 离散事件按因果方向对齐；
4. 记录最大时间误差；
5. 检查动作到实际响应的系统延迟。

训练动作 $a_t$ 应对应哪个观测时刻取决于控制定义和延迟。盲目按最近时间戳匹配可能把“动作后的画面”当成动作前条件，形成信息泄漏。

## 11.6 归一化

常见方法：均值/标准差、min-max、分位数裁剪。原则：

- 统计量只由训练集计算；
- 每种动作语义和本体分别审计；
- 常数维度避免除零；
- 推理必须携带同一统计量；
- 对重尾和极端值查看分位数，而不是只看均值。

归一化错误通常不会报异常，只会产生幅度错误动作，是最危险的静默故障之一。

## 11.7 质量控制

自动检查：

- NaN/Inf、时间倒退、重复帧；
- 速度/加速度/jerk 异常；
- 图像丢失、黑帧、曝光异常；
- 动作超限、夹爪状态不一致；
- 成功标签与轨迹末状态矛盾；
- 数据分布和元数据缺口。

人工检查应使用分层抽样，不只看随机成功样本。重点抽查长轨迹、极端动作、失败、接管和低置信度样本。

## 11.8 数据划分与污染

按 episode、对象实例、场景和任务划分，具体取决于声称的泛化维度。相邻帧或同一初始场景跨 train/test 会产生泄漏。

预训练 VLM 可能见过测试对象图片和任务文本。需要区分：

- 视觉语义预训练见过类别；
- 机器人动作训练见过任务；
- 测试场景是否复刻训练资产；
- 测试数据是否被调参反复使用。

“未见过”必须具体到对象实例、类别、布局、指令或本体。

## 11.9 数据增广与合成

- 图像增广：颜色、裁剪、遮挡，但要保持动作和语言标签一致。
- 轨迹扰动：加入状态偏移并配恢复标签。
- 轨迹重定向：随物体位姿变换动作段，需重新验证碰撞与成功。
- 仿真程序化生成：扩大布局和外观。
- 生成视频/世界模型：扩大视觉变化，但动作一致性和物理正确性必须过滤。

合成数据不是免费真值。应报告生成成功率、过滤规则、与真机数据的性能相关性和负迁移。

## 11.10 多数据集与跨本体

混合数据前建立转换层：

```text
source schema -> validated canonical schema -> model adapter
```

需要显式处理动作空间、相机视角、频率、任务语言、成功定义和采样权重。混训涨点可能只是总数据量增加，必须与“等量目标本体数据”及“只用目标本体数据”比较。

## 11.11 版本、许可证与隐私

数据版本应绑定：原始来源、处理代码提交、过滤配置、统计摘要和哈希。训练 checkpoint 必须能追溯到数据版本。

使用公开数据前核对许可证、商用限制、人物隐私和再分发要求。真机视频可能包含人脸、住址、屏幕和语音，采集前应制定最小化和脱敏策略。

## 11.13 自测题

1. 为什么 trajectory 和 token 不能直接比较数量级？
2. 动作回放可视化为什么应在训练前完成？
3. 相机和控制数据按最近时间戳匹配可能产生什么因果错误？
4. “未见过的对象”至少有哪些不同定义？
5. 如何证明跨本体混训收益不是单纯来自更多数据？
