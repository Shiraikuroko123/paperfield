# M4.6 专题：跨本体基础模型

> 锚点：GR00T N 系列（NVIDIA）、RDT（清华）；前置：第 05、06、07 课

## 一、问题定义

跨本体（cross-embodiment）：让一个模型驱动**不同形态**的机器人——不同的臂、不同自由度的手、轮式底盘、人形。为什么值得追求：①数据合并——所有机器人的数据喂一个模型，正面攻击数据瓶颈；②技能迁移——A 机器人学的经验 B 能用；③商业逻辑——"机器人界的安卓"。

难在哪：不同本体的**动作空间根本不同**（6 自由度臂 vs 7 自由度臂 vs 五指手），观测视角不同，动力学不同。互联网文本没有这个问题（全世界的文字都是 token），这是具身智能独有的难题。

## 二、GR00T N1：双系统架构

NVIDIA 的开源人形基础模型，架构是教科书级的"快慢双系统"：

```
System 2（慢，~10Hz）：VLM（Eagle 系列）— 看图理解指令，出"意图"
System 1（快，~120Hz）：DiT 动作头（flow matching）— 意图+状态 → 高频动作
```

训练数据是完整的**数据金字塔**实践：真机遥操作 + 仿真数据 + **GR00T-Dreams 世界模型合成数据**（用视频生成模型"想象"机器人干活，再反推动作标签）+ 人类视频。M4.3 数据问题专题的金字塔在这里全用上了。

跨本体处理：本体状态和动作用**每种机器人各自的编码/解码头**投影到共享潜空间，中间的大脑共享。

## 三、RDT：中国队的代表作

清华 RDT-1B：**扩散 Transformer** 路线的双臂操作基础模型，1.2B 参数（当时最大的操作扩散模型）。关键贡献是**统一动作空间**设计：定义一个覆盖各种机器人的"物理可解释统一动作向量"（各关节、末端位姿、夹爪等位置对齐），异构数据填入对应槽位，缺的置空——用工程化方案硬解动作异构问题。在双臂灵巧任务（倒水控制水量、折叠衣物）上做出了当时最强的泛化演示。后续 RDT2 继续沿"统一动作空间+更大数据"迭代。

## 四、跨本体的真实现状（批判）

1. **"一个大脑"更多是营销，"一个底座"才是现实**：所谓跨本体模型，实际部署时几乎都要对目标本体做微调；zero-shot 换身体仍不可靠
2. **负迁移真实存在**：形态差异大的数据混训可能互相拖累（轮式底盘数据帮不了五指手），怎么配比、怎么分组是开放问题
3. **统一动作空间的表达瓶颈**：RDT 式槽位对齐处理不了根本不同的执行器（吸盘 vs 五指手）
4. **评测更难了**：跨本体泛化怎么公平衡量？换一个没见过的机器人测——但"没见过"的程度无标准（M6.2 评测危机专题又见）

## 五、复试级问答

**Q1：跨本体为什么难？主流的三类解法？**
要点：难在动作/观测/动力学三重异构。解法：①各本体独立编解码头+共享中间大脑（GR00T）；②统一动作空间对齐（RDT）；③以语言/子任务为中间表示，本体细节交给底层控制器（分层，M4.7 LLM Agent 专题）。加分：指出三者可组合，且都没根治 zero-shot 换体。

**Q2：GR00T 的双系统设计，为什么不用一个模型端到端到底？**
要点：频率矛盾——VLM 推理 10Hz 级，控制需要 100Hz 级；参数矛盾——语义理解要大模型，实时控制要小模型。双系统 = 各干各的擅长活，通过潜向量接口衔接。追问预备：接口设计（传什么给 System1）是信息瓶颈，传少了语义丢失，传多了 System1 变慢——这是该架构的固有张力。

**Q3：你怎么看"机器人安卓"的商业叙事？**
开放题。参考立场：技术上底座共享已被证明有效（数据合并涨点），但"安卓时刻"需要两个前提尚未满足——①某种本体形态出货量足够大形成标准（人形 or 轮式双臂之争未决）；②接口标准化（动作空间、传感器规格）。可以引用手机类比的失效处：手机硬件高度同质，机器人硬件极度异质。有理有据地存疑，比无脑看多看空都加分。

## 工程视角附录

**GR00T 微调流程**（`NVIDIA/Isaac-GR00T` 仓库）：

```text
1. 你的数据 → LeRobot 格式（M4.3 数据问题专题的格式在这里复用）
2. 写 modality.json：声明你的本体——几个相机、几个关节、动作维度与含义
3. 选 embodiment tag（新本体 = 新的编解码头）
4. 微调：数据 <100 条 → 冻结底座只训动作头；数据充足 → 全参微调
```

**RDT 统一动作空间的实现**：一个 128 维"物理槽位"向量，每个槽位有固定物理含义（右臂关节 1 角度、左夹爪宽度……）。各机器人按语义把自己的动作填入对应槽，缺省槽置 0 并用 mask 标记。异构数据从此可以堆在同一个 batch 里。

**常见坑**：
1. **槽位/动作映射填错 = 静默灾难**：训练照常收敛，部署动作全错。铁律：训练前先把数据集里的动作序列在仿真里回放可视化一遍，眼见为实
2. 新本体小数据微调时动作头过拟合快，早停要激进
3. 视频解码常成训练吞吐瓶颈（GPU 等 CPU 解码）——预解码成帧或用 NVDEC
4. 跨本体"涨点"要做对照：混训 vs 只用本体数据，别把数据量增加的功劳记给跨本体
