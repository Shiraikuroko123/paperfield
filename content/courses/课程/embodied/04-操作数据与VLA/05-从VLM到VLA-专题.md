# M4.5 专题：从 VLM 到 VLA

> 锚点论文：RT-2（Google DeepMind, 2023）、OpenVLA（Stanford 等, 2024）

## 一、动机：单任务模仿的天花板

ACT/DP 再强也是"一个任务一个模型"，且不懂语言。而同期（2023）VLM 已经能看图说话、有海量世界知识。自然的问题：**能不能让"见过整个互联网"的模型直接输出机器人动作？** 这就是 VLA（Vision-Language-Action）。

前置：RT-1（2022）用 13 台机器人采了 17 个月、13 万条示范，训了一个多任务 Transformer，证明"多任务大数据"路线可行，但模型从零训练、没有互联网知识。

## 二、RT-2：动作即语言

核心招数简单到惊人：**把动作离散成 256 个 bin，当作"文字 token"直接混进 VLM 的词表**。7 维动作（xyz + 旋转 + 夹爪）= 一句 8 个"字"的话。然后把机器人数据和互联网视觉语言数据**联合微调**（co-fine-tuning）一个 55B 的 PaLI-X。

结果出现了**语义泛化**：训练数据里从没有"把草莓放进正确的碗""捡起濒临掉落的物体""用石头当锤子"，但模型做到了——因为"草莓""濒临掉落""锤子"的概念来自互联网预训练。**这是 VLA 路线的立身证据：互联网知识可以流进动作。**

## 三、OpenVLA：7B 打败 55B，且开源

| 设计 | RT-2 | OpenVLA |
|---|---|---|
| 底座 | PaLI-X 55B（闭源） | Prismatic 7B = SigLIP+DINOv2 双视觉编码 + Llama-2 |
| 数据 | Google 自家机器人数据 | Open X-Embodiment 97 万条（22 种机器人） |
| 动作表示 | 离散 token | 离散 token（同款） |
| 开放性 | 论文 only | 权重、代码、数据配方全开 |

在 29 个任务的对比中 OpenVLA 以 1/7 的参数量比 RT-2-X 高 16.5%。两个启示：①**架构与数据质量 > 参数量**；②双视觉编码器有讲究——SigLIP 管语义、DINOv2 管空间细节（抓取需要毫米级空间感）。LoRA 微调单张消费级 GPU 即可——这是你未来能亲手碰 VLA 的原因。

## 四、共同软肋与演化方向（批判即路线图）

1. **自回归离散动作太慢**：一个 token 一个 token 吐，控制频率只有几 Hz，精细/动态任务不够用 → 后续 OpenVLA-OFT：并行解码+连续动作头，吞吐量提升数十倍 → π0 直接改 flow matching 连续动作（M3.6 π0 与 flow matching 专题）
2. **离散化损失精度**：256 bin 对毫米级操作太粗
3. **无记忆**：单帧输入，长时序任务（先开抽屉再放东西再关上）容易迷路 → 2026 年的记忆机制研究（MemER 等）
4. **数据异构税**：OXE 里不同机器人坐标系、相机位、动作定义不同，简单混训有负迁移 → 跨本体对齐（M4.6 跨本体专题）
5. **评测在自家场景**：泛化声明的可信度问题（M6.2 评测危机专题埋钩子）

看懂了吗：**每一条批判都是一篇后续顶会论文的出生证明。** 学会这个视角，你就会自己找 idea 了。

## 五、复试级问答

**Q1：VLA 与"VLM 规划 + 底层控制器执行"的分层方案，各自优劣？**
要点：VLA 端到端——语义知识直通动作、无接口信息损失，但不可解释、出错难定位、数据饥渴；分层——模块可换可调试、底层可用经典控制保精度，但接口（语言/技能库）成为表达瓶颈，"把香蕉掰成两半"这类连续接触任务难以用离散技能表达。当前趋势是折中：快慢双系统（M4.7 LLM Agent 专题）。

**Q2：RT-2 的"语义泛化"具体指什么？为什么 ACT 做不到？**
要点：对训练动作数据中不存在、但互联网语义中存在的概念做出正确操作（草莓/灭绝动物玩偶/石头当锤子）。ACT 从零训练、只见过 50 条示范，权重里没有世界知识可供迁移。一句话：**泛化的来源不是机器人数据，是互联网预训练**。

**Q3：如果让你改进 OpenVLA，你先动哪里？**
要点（任选其一深入即可）：①动作头——离散换连续（flow matching/扩散），提频提精度；②加记忆——多帧/显式记忆模块；③数据——OXE 清洗与配比（数据质量方向常被低估）；④推理加速——蒸馏小模型部署。加分：说明你选的方向"改动小、可验证、单卡能做"——顺便这就是你复现冲刺的候选 idea。

## 工程视角附录

**动作 token 化的实现细节**：

```python
bins = linspace(-1, 1, 256)
a_norm = normalize(a, dataset_stats)          # 按数据集分位数归一
a_tokens = digitize(a_norm, bins)             # 7 维动作 → 7 个 token
# 这 256 个 token 直接占用 Llama 词表中最少使用的 256 个位置
prompt = "In: What action should the robot take to {指令}?\nOut:"
# 推理：自回归生成 7 个 token → 反查 bin 中心 → 反归一化 → 动作
```

**LoRA 微调**（单张 24G 卡可跑，你未来的入场券）：`openvla/openvla` 仓库 `finetune.py`，关键参数 lora_rank 32 / lr 5e-4 / 梯度累积凑 batch 16 / 数据转成 LeRobot/RLDS 格式。推理约 16G 显存，4bit 量化可再降一半。

**常见坑**：
1. **unnorm_key 选错**：反归一化用哪套数据集统计必须显式指定，选错则动作全错但不报任何错——OpenVLA 新手第一坑
2. prompt 必须和训练时逐字符一致（多个空格都不行）
3. 图像预处理（分辨率 224、归一化均值方差）必须匹配预训练配置
4. 评测用 LIBERO/SimplerEnv 公共协议，自造场景的结论没人信（M6.2 评测危机专题）
