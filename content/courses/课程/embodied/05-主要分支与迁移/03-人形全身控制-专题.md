# M5.3 专题：人形全身控制与 loco-manipulation

> 锚点：HOVER（NVIDIA）、SkillBlender；前置：M3.2 RL 与运动控制专题 RL 运动控制

## 一、从"会走"到"能干活"，差了三级台阶

M3.2 RL 与运动控制专题的四足/人形行走只解决了"移动"。人形机器人的卖点是**在人类环境里干人类的活**，这需要：

1. **全身协调（whole-body control）**：弯腰搬箱子时，手、腰、腿、重心是一个耦合问题——手一伸重心就变，腿必须补偿
2. **运动-操作一体（loco-manipulation）**：边走边推车、扶着栏杆下楼梯，移动与操作不再分家
3. **类人动作质量**：不只是"不摔倒"，还要动作自然（进家庭/服务场景的隐性刚需）

自由度 30-50+，接触模式复杂多变，奖励塑形（M3.2 RL 与运动控制专题的手艺）在这里彻底炼不动了——每个动作都手调奖励不可扩展。

## 二、范式转移：从"炼奖励"到"模仿人类动作"

关键思想：**人类动作捕捉数据（mocap）里藏着全身协调的答案**，不用再手工设计。流水线：

```
人类 mocap 数据（AMASS 数据集等）
  → 重定向（retargeting）：人体骨架 → 机器人关节（体型不同，需映射）
  → RL 训练"动作跟踪"策略：奖励由参考动作跟踪和防摔项组成（奖励从此不用炼了）
  → 蒸馏：多个跟踪策略 → 一个通用策略
```

代表工作梯队：
- **H2O / OmniH2O**：人类视频/动捕实时遥操作人形，全身跟踪
- **ExBody2**：表达性全身动作跟踪，动作质量显著提升
- **HOVER**（NVIDIA）：把多种控制模式（跟踪头手、跟踪全身关节、只跟踪根方向……）**蒸馏进一个统一策略**，一个网络支持多种上游接口——"全身控制的通用底座"思路
- **SkillBlender**：预训练一组基元技能（走、蹲、伸手），新任务用轻量权重**混合**基元完成 loco-manipulation——组合优于从零学

进度真相：**下半身已接近解决（各家人形都能稳走），上半身+双手才是主战场**；全身控制提供"身体底座"，上面接 VLA 大脑（M4.6 跨本体专题 GR00T 的 System1 就是这类控制器）。

## 三、批判（复试杀手锏）

1. **重定向失真**：人和机器人体型、质量分布、关节极限不同，映射后的"参考动作"对机器人可能物理不合理，跟踪它反而有害；重定向质量是被低估的瓶颈
2. **跟踪 ≠ 理解**：模仿动作外形，不懂动作目的——搬箱子的 mocap 学会了"搬的姿势"，箱子重量变了就露馅（无力控/力感知）
3. **力交互是盲区**：当前范式以位置控制为主，拧螺丝、推重物这类力主导任务基本空白
4. **能耗与硬件磨损**：RL 策略动作"抖"，真机长时间跑关节磨损严重——学术评测从不报告这个，工业界很在乎

## 四、复试级问答

**Q1：为什么全身控制不再用M3.2 RL 与运动控制专题那套奖励塑形？**
要点：自由度爆炸（40+）× 任务多样 → 每任务手调奖励不可扩展；且"自然度"无法写成奖励项。Mocap 跟踪范式把奖励简化成"跟上参考"，把设计负担转移给了数据（人类动作库）——又是一次"工程手艺被数据取代"的领域规律。答出这个规律，考官会眼前一亮。

**Q2：HOVER 的"多模式蒸馏成一个策略"有什么价值？**
要点：不同上游（VR 遥操作给头手位姿、VLA 给根速度+末端目标、动捕给全身关节）需要不同控制接口；分开训 N 个策略则切换生硬、部署臃肿。统一策略 = 一个底座适配多种大脑接口，是"身体基础模型"的雏形。追问预备：代价是各模式间可能互相牵制，单模式性能略降。

**Q3：人形机器人是不是伪需求？（复试真的会问）**
参考立场（答"有条件的真需求"最稳）：支持——人类环境为人形设计（楼梯、门把手、工位），通用形态摊薄单位成本、共享数据飞轮；反对——绝大多数单一任务用轮式+双臂更便宜可靠，双足的能耗与可靠性税很重。结论：短期专用形态落地更快，长期通用性价值取决于"一脑多任务"是否成立——把答案锚定到技术判断而非站队，显成熟。

## 工程视角附录

**动作跟踪训练的关键机关**（伪代码级）：

典型动作跟踪奖励可以写成

$$
r_t=
w_q\exp\!\left(-\lVert q_t-q_t^{\mathrm{ref}}\rVert_2^2\right)
+w_x\exp\!\left(-\lVert x_t-x_t^{\mathrm{ref}}\rVert_2^2\right)
-w_\tau\lVert\tau_t\rVert_2^2
-w_a\lVert a_t-a_{t-1}\rVert_2^2.
$$

```python
ref = retarget(amass_clip, robot)        # IK+骨架缩放；脚滑/穿地要后处理清理
joint_error = squared_distance(q, ref.q)
keypoint_error = squared_distance(key_pos, ref.key_pos)
reward = tracking_reward(joint_error, keypoint_error, torques, actions)
# 两个不起眼但决定成败的机关：
init  = RSI(ref)      # Reference State Init：随机从参考轨迹中段"出生"
                      # 否则策略永远练不到动作后半段
done  = tracking_error > threshold  # 早期终止：跟丢就重开
                      # 否则摔倒后乱扑腾也在刷奖励
student = dagger_distill(teacher, proprioceptive_history)
```

**仓库导读**：入门读 `unitree_rl_gym`（宇树官方，对应它家真机）；进阶读 PHC / H2O / ExBody 系列开源代码。人类动作数据用 AMASS（需在官网申请许可）。

**常见坑**：
1. retarget 伪影不清理（脚滑步、穿地、自碰撞），策略会把病一起学走——**跟踪质量上限 = 参考质量**
2. RSI 和早期终止漏配任何一个，训练直接不收敛，新手以为是超参问题白调一周
3. 蒸馏 student 时要在仿真里注入观测延迟，否则真机相位滞后
4. 真机第一次跑：低 PD 增益 + 吊架保护 + 手在急停上
