## 1. 怎么使用这门课

课程只有一条顺序：

    M0 导学与诊断
      -> M1 数学与学习基础
      -> M2 机器人系统基础
      -> M3 策略学习
      -> M4 操作、数据与 VLA
      -> M5 主要分支与迁移
      -> M6 研究、评测与项目

同一序列中有两种单元：

| 单元类型 | 学习方式 | 完成标准 |
|---|---|---|
| 主干 | 学定义、公式和系统机制，运行对应实验 | 能计算或实现，并解释一次失败 |
| 专题 | 阅读前沿脉络和论文图表，训练批判与表达 | 不看原文讲清问题、方法、证据和局限 |

不要把专题连续刷完，也不要把“听懂术语”当成掌握。每个专题已经放在它所依赖的主干内容之后。

完成全部课程后，应当能够：

1. 用“观测、状态、策略、动作、控制、环境”描述具身系统。
2. 看懂位姿、雅可比、动力学、概率模型、优化和策略学习中的常见公式。
3. 使用 Python、NumPy 和 PyTorch 实现、训练并调试小型模型。
4. 区分规划、控制、强化学习、模仿学习和 VLA 各自解决的问题。
5. 理解硬件、传感器、ROS2、仿真、数据和 Sim2Real 的系统约束。
6. 完成一个可复现项目，并用统计证据而不是精选 demo 支撑结论。
7. 阅读前沿论文时分清事实、实验结论、作者解释和产业叙事。

## 5. 单元学习闭环

### 主干单元

1. 预测：先看学习目标，写下自己会怎么解释。
2. 理解：读正文，推导至少一个关键公式。
3. 执行：运行实验，主动改一个参数制造失败。
4. 检索：阅读给出的原始资料，而不是只看二手总结。
5. 输出：完成自测；能解释失败原因才算掌握。

### 专题单元

1. 不看原文，用三分钟说明问题、方法、证据和局限。
2. 打开锚点论文，至少检查一张架构图和一张关键实验表。
3. 回答专题问题，并指出一个有证据支持的真实弱点。
4. 说清它与前面主干单元的关系。

时间非常紧时只读专题中的“批判”和“复试问答”，但这只算保持领域体感，不算掌握。

### 2026-12-19前每周模板

| 环节 | 建议时间 | 产出 |
|---|---:|---|
| 主干阅读两次 | 2 × 45 分钟 | 一页自己的笔记 |
| 实验或自测 | 60 分钟 | 运行记录和一个失败解释 |
| 专题复述 | 30 分钟 | 脱稿讲清动机、方法、证据和局限 |

合计不超过 3 小时。某个单元没有读懂时，下周继续，不以日期强行翻篇。

## 7. 项目与方向选择

### 项目 0：把现有工业视觉系统补成证据闭环

这个项目用于把已有工程优势转化为研究能力，不把工业缺陷检测本身当作最终具身智能方向。若仍能取得代码、模型和脱敏测试图像，优先完成：

| 工作 | 最低产出 |
|---|---|
| 固定测试集与数据说明 | 图像来源、标注规则、划分方式和版本 |
| 模型效果评测 | precision、recall、F1，以及适合分割任务的 mask IoU 或 mAP |
| 系统实时性评测 | 端到端时延的中位数和 P95、吞吐量、丢帧或覆盖率 |
| 一个受控对照 | 比较置信度阈值、输入分辨率或帧队列策略中的一个变量 |
| 失败分类 | 漏检、误检、格式转换、模型加载、设备断连等可复查案例 |
| 可复现与测试 | 环境版本、外置配置、文件日志、一条评测命令和关键模块自动测试 |

没有真实数据就不编造指标。无法取得原项目材料时，使用公开分割数据和同一 ONNX 推理链完成等价评测。完成后再进入 ACT、Diffusion Policy 或机器人控制项目。

### 三条试探方向

| 方向 | 核心问题 | 第一个试探项目 | 常用工具 |
|---|---|---|---|
| 操作与 VLA | 机器人如何根据视觉和语言完成操作 | 在仿真数据上复现 ACT 或 Diffusion Policy | LeRobot、MuJoCo、LIBERO |
| 运动控制 | 腿式或人形机器人如何稳定运动和全身协同 | 训练一个小型行走策略并分析奖励和随机化 | Isaac Lab、Gymnasium |
| 仿真、数据与世界模型 | 数据如何生成、清洗、迁移和评测 | 审计数据集或复现一个最小 Sim2Real 流程 | LeRobotDataset、MuJoCo |

方向试探必须有可重复代码、公平 baseline、一个受控变量、失败案例和资源记录。基础 labs 使用 CPU；大型 VLA 微调、Isaac Lab 并行训练和大规模评测再使用云 GPU。

## 8. 研究生阶段

| 时间 | 主任务 | 验收产出 |
|---|---|---|
| 入学前 | 完成 M0-M6 和一个最小项目 | 完整实验报告与演示 |
| 研一上 | 对操作、运动、数据三条线各做一次小试探 | 三份短报告，与导师确定主线 |
| 研一下 | 精读主线论文并深度复现代表作 | 公开笔记、复现、至少一个消融 |
| 研二 | 从复现中的缺陷提出可检验改进 | 完整研究工作和投稿 |
| 研三 | 扩展代表作、整理开源与毕业论文 | 可维护代码、论文和毕业材料 |

科研循环固定为：

    复现论文 -> 找到失效条件或未验证假设
             -> 提出最小改动
             -> 公平 baseline 与消融
             -> 统计评测和失败分析
             -> 写作、开源、投稿

重要论文必须配代码或实验。会议时间每年可能变化，只在准备投稿时查当年官网，不在长期路线中写死截稿日期。

## 10. 不变规则

1. 初试优先，暂停不等于失败。
2. 领域新手先补缺失依赖，再看 VLA 热点。
3. 读懂不等于会做，至少经过计算、实现和失效分析。
4. 仿真优先，真机必须有安全边界和人工接管。
5. 前沿结论标注日期，并回到论文、代码和公开评测核查。
6. 每个阶段只维护一个主项目，避免同时开多个环境和仓库。
