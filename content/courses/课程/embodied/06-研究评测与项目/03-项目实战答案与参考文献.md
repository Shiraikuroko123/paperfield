# M6.3 主干：项目实战、验收与继续学习

## 学习目标

本章把前 16 章变成可检查的产出。项目按算力分级；完成标准是别人能复现你的结果，而不是模型“看起来跑起来了”。

## 17.1 项目 0：环境与数值基础

**算力**：CPU，1-2 天。

任务：运行 `labs/00-10`，为每个实验修改一个关键参数并解释变化。

验收：

- 所有脚本无异常退出；
- 输出中不含 NaN/Inf；
- 固定随机种子后关键指标一致；
- 写一页失败实验记录，不只保存成功结果。

## 17.2 项目 1：二维机械臂闭环到达

**算力**：CPU，1 周。

目标：把 FK/IK、雅可比和 PD 控制连接成完整系统。

步骤：

1. 采样工作空间内外目标。
2. 用解析或数值 IK 产生关节目标。
3. 用二阶动力学和 PD 跟踪。
4. 加入关节限位、动作饱和、测量噪声和 20-100 ms 延迟。
5. 报告位置误差、稳定时间、超调、限幅次数和不可达率。

验收：至少 100 个固定测试目标；给出置信区间或分布；展示奇异、不可达和高延迟三类失败。

## 17.4 项目 3：公开仿真操作复现

**算力**：推荐 NVIDIA 12-24 GB 显存，2-6 周。

可选 LIBERO、robomimic 或 LeRobot 支持的轻量仿真任务。选择 ACT 或 Diffusion Policy 作为主方法，另选一个公平 baseline。

执行顺序：

1. 固定仓库提交、Python/CUDA/仿真器版本。
2. 先运行官方最小配置和预训练 checkpoint。
3. 可视化数据和动作回放。
4. 只用一个 batch 验证能过拟合。
5. 小数据短训练跑通端到端。
6. 锁定协议后进行多 seed 正式训练。
7. 报告失败类型、置信区间、训练时间和推理延迟。

验收：README 中一条命令可复现实验；公开配置、日志、聚合结果和至少 20 条连续失败/成功评测，而不是剪辑视频。

## 17.5 项目 4：VLA 微调或系统性评测

**算力**：取决于模型；通常需要独立 GPU 或远程算力，4-10 周。

两条路线：

- 微调路线：冻结底座或 LoRA，研究数据量、动作归一化或动作头。
- 评测路线：固定公开 checkpoint，系统改变语言、光照、对象、布局、延迟或安全过滤。

低算力学习者优先做评测路线，因为它更容易分离变量。不要把一次 LoRA 成功运行称为研究贡献。

验收：预注册主要假设；至少一个公共 benchmark；与同协议 baseline 比较；多 seed 或充分任务分层；统计不确定性；完整失败分类。

## 17.6 算力选择

| 层级 | 适合内容 | 不适合内容 |
|---|---|---|
| 本地 CPU/集显 | 本教材实验、数学、数据审计、小网络 | Isaac 大规模 RL、大 VLA 微调 |
| 消费级 NVIDIA GPU | ACT/DP 小任务、部分 LoRA、仿真 | 大规模预训练、多机训练 |
| 实验室/租用 GPU | 多 seed benchmark、Isaac Lab、VLA 微调 | 未经预算的无限试错 |
| ChatGPT Work/Codex Cloud | 仓库分析、代码修改、测试、长任务 | 不应假定有 GPU或固定训练规格 |

ChatGPT Work 的 Cloud 模式是托管任务环境；公开资料未承诺固定 CPU、RAM 或 GPU。需要 CUDA 的项目应使用明确标注 GPU 型号、显存、时长和价格的计算资源。

## 17.9 毕业标准

达到以下标准，才建议把研究方向收窄到 VLA、人形、数据或世界模型：

1. 可以解释传感器到电机的完整闭环。
2. 可以读懂至少一个开源仓库的训练和评测入口。
3. 可以定位坐标、单位、时间、归一化和 checkpoint 问题。
4. 可以用置信区间、多 seed 和失败分类支持结论。
5. 完成一个第三方可复现项目。
6. 对一个前沿方向能同时给出动机、证据、局限和可验证问题。
